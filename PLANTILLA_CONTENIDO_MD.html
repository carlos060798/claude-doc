Plantilla HTML Reutilizable para Integración de Contenido .md

Este documento describe la estructura, clases CSS y patrones HTML para convertir sistemáticamente archivos .md a secciones HTML integradas en index.html.

Objetivo: Crear un sistema escalable donde cada sección de módulo .md se traduce a HTML siguiendo una plantilla consistente, permitiendo que cualquier contenido .md se integre sin rediseñar el layout.

1. Estructura de Sección Base

Cada sección de contenido .md debe estar envuelta en esta estructura HTML base:

<!-- ====== SECCIÓN: [NOMBRE-DEL-MODULO] ====== -->
<section class="content-section"
         data-section="[nivel-X-modulo-Y]"
         data-mode="technical">

    <!-- Header con navegación y descripción -->
    <div class="section-header">
        <span class="breadcrumb">Nivel X / [Nombre]</span>
        <h2>[Icono] [Título Principal]</h2>
        <p class="section-lead">
            Párrafo introductorio de 1-2 líneas describiendo
            el propósito del módulo.
        </p>
    </div>

    <!-- Contenido estructurado (h3, p, listas, tablas, código) -->
    <!-- ... (ver secciones 2-7 abajo) ... -->

</section>
Atributos críticos:
  • data-section="nivel-X-modulo-Y" — Identificador único, sincronizado con el nav del sidebar
  • data-mode="technical" — "technical" | "accessible" | "both" (filtra visibilidad por modo)
  • class="content-section" — Controlada por JavaScript para mostrar/ocultar

2. Componentes de Texto Base

2.1 Títulos (h2, h3, h4)

Ejemplo HTML:

<!-- Título principal de sección -->
<h2>Icono Troubleshooting Avanzado</h2>

<!-- Subtítulos de contenido -->
<h3 class="block-title">🔧 Diagnóstico de Problemas</h3>

<!-- Subsecciones de contenido -->
<h4>Paso 1: Recopilar evidencia</h4>
Clases CSS aplicadas:
  • .block-title — h3 principal con borde izquierdo orange (#ff7a59)
  • Los h2 heredan de .section-header h2 (color azul, línea naranja debajo)
  • Los h4 heredan color púrpura (#d084fc)

2.2 Párrafos y Descripción

Ejemplo HTML:

<p>
    Texto normal de párrafo. Pueden contener <strong>bold</strong>,
    <em>italic</em>, y <code>código inline</code>.
</p>

<p class="section-lead">
    Párrafo introductorio más grande. Usado después de h2 principal
    para describir el módulo. Color secundario.
</p>

3. Listas (ul, ol)

3.1 Listas Desordenadas

Ejemplo HTML:

<h3 class="block-title">📋 Problemas Comunes</h3>
<ul class="bullet-list">
    <li>Token de contexto agotado</li>
    <li>Conexión a MCP rechazada</li>
    <li>Error de permisos en archivo</li>
</ul>

3.2 Listas Ordenadas (Pasos)

Ejemplo HTML:

<h3 class="block-title">🔍 Flujo de Diagnóstico</h3>
<ol class="step-list">
    <li><strong>Verificar contexto:</strong> Usar /context para ver tokens restantes</li>
    <li><strong>Revisar logs:</strong> Activar DEBUG=1 para ver output detallado</li>
    <li><strong>Aislar variable:</strong> Reducir input hasta encontrar la causa</li>
</ol>
Nota: Las listas heredan estilos de ul, ol en styles.css (márgenes, colores, font).

4. Bloques de Código

4.1 Código Inline

Para código dentro de párrafos, usar <code> directo. Se estiliza con fondo oscuro y color azul.

4.2 Bloques de Código (pre/code)

Ejemplo HTML:

<h3 class="block-title">⚙️ Comando: Verificar Token</h3>
<div class="code-block" data-lang="bash" data-title="Terminal">
    <pre><code>$ claude /context --tokens
Token usage: 4,250 / 200,000 (2.1%)
Window size: 3,900 tokens
  - System: 800
  - Conversation: 3,100</code></pre>
</div>
Atributos del div.code-block:
  • data-lang="bash|python|javascript|text|json" — Tipo de lenguaje (para syntax highlighting futuro)
  • data-title="Terminal|Código|Salida" — Etiqueta visible en la esquina
  • data-note="typescript" (opcional) — Nota adicional a mostrar

4.3 Variante: Código con explicación lado a lado

Ejemplo HTML:

<div class="grid-2col">
    <div>
        <h4>Problema</h4>
        <div class="code-block" data-lang="text" data-title="Error">
            <pre><code>Error: ENOMEM (out of memory)</code></pre>
        </div>
    </div>
    <div>
        <h4>Solución</h4>
        <div class="code-block" data-lang="bash" data-title="Comando">
            <pre><code>claude /compact "mantén últimas 3 llamadas"</code></pre>
        </div>
    </div>
</div>

5. Cajas Destacadas (Info, Notas, Warnings, Ejemplos)

5.1 Nota Importante (Naranja)

Ejemplo HTML:

<div class="highlight-box">
    <strong>💡 Pro Tip:</strong> Mantén logs de ejecución para
    reconstruir contexto en sesiones futuras.
</div>
💡 Pro Tip: Mantén logs de ejecución para reconstruir contexto en sesiones futuras.

5.2 Aviso / Warning (Amarillo)

Ejemplo HTML:

<div class="warning">
    <strong>⚠️ Cuidado:</strong> No uses /compact si hay tokens
    sin procesar. Puede causar pérdida de contexto crítico.
</div>
⚠️ Cuidado: No uses /compact si hay tokens sin procesar. Puede causar pérdida de contexto crítico.

5.3 Información (Verde)

Ejemplo HTML:

<div class="notas-css">
    <strong>ℹ️ Información:</strong> Este comando solo funciona
    en sesiones nombradas o con CLAUDE.md activo.
</div>
ℹ️ Información: Este comando solo funciona en sesiones nombradas o con CLAUDE.md activo.

6. Tablas

6.1 Tabla Simple (Matriz de Decisión)

Ejemplo HTML:

<h3 class="block-title">📊 Matriz: ¿Cuándo usar cada comando?</h3>
<table>
    <thead>
        <tr>
            <th>Comando</th>
            <th>Cuándo usarlo</th>
            <th>Costo (tokens)</th>
            <th>Alternativa</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td><code>/context</code></td>
            <td>Diagnosticar uso actual</td>
            <td>~100</td>
            <td>Ninguna</td>
        </tr>
        <tr>
            <td><code>/compact</code></td>
            <td>Sesiones largas (>4h)</td>
            <td>~200</td>
            <td>Nueva sesión</td>
        </tr>
    </tbody>
</table>

7. Matrices de Decisión (Tablas Especiales)

Para matrices complejas con múltiples dimensiones, usar grid CSS:

Ejemplo HTML:

<h3 class="block-title">🗺️ Matriz de Decisión: ¿Cuál es tu caso?</h3>
<div class="grid-3col">
    <div class="decision-card">
        <h4>📦 Caso: Token Budget</h4>
        <p><strong>Síntoma:</strong> Sesión mayor a 2 horas</p>
        <p><strong>Solución:</strong></p>
        <ol>
            <li>Usar /compact</li>
            <li>Seleccionar qué preservar</li>
            <li>Continuar</li>
        </ol>
    </div>

    <div class="decision-card">
        <h4>🔗 Caso: MCP Falla</h4>
        <p><strong>Síntoma:</strong> "Connection refused"</p>
        <p><strong>Solución:</strong></p>
        <ol>
            <li>Verificar puerto</li>
            <li>Restart servidor</li>
            <li>Reconectar</li>
        </ol>
    </div>

    <div class="decision-card">
        <h4>🚀 Caso: Rendimiento</h4>
        <p><strong>Síntoma:</strong> Respuestas lentas</p>
        <p><strong>Solución:</strong></p>
        <ol>
            <li>Revisar logs</li>
            <li>Reducir input</li>
            <li>Perfilar tiempo</li>
        </ol>
    </div>
</div>

8. Estructura de Nodo de Sección Completa

Aquí está el árbol HTML completo de una sección (ejemplo: nivel-5-troubleshooting):

<section data-section="nivel-5-troubleshooting" data-mode="technical"> <div class="section-header"> <span class="breadcrumb">Nivel 5 / Troubleshooting</span> <h2>🔧 Troubleshooting Avanzado</h2> <p class="section-lead">...</p> </div> <!-- Bloque 1: Introducción --> <h3 class="block-title">Diagnóstico 101</h3> <p>...</p> <ul>...</ul> <!-- Bloque 2: Código --> <h3 class="block-title">Comandos Útiles</h3> <div class="code-block">...</div> <!-- Bloque 3: Matriz --> <h3 class="block-title">Matriz de Decisión</h3> <div class="grid-3col">...</div> <!-- Bloque 4: Tabla --> <table>...</table> <!-- Bloque 5: Warnings --> <div class="highlight-box">...</div> </section>

9. Clases CSS Esenciales

Clase CSS Aplicar a Propósito Notas
content-section <section> Contenedor principal de cada módulo Mostrado/ocultado por JS
section-header <div> Encabezado con breadcrumb + h2 + lead Animación slideInDown
breadcrumb <span> Texto de navegación pequeño (Nivel X / Nombre) Color muted, uppercase
section-lead <p> Párrafo introductorio grande fs-lg, color-secondary
block-title <h3> Título de bloque de contenido Borde izquierdo naranja
code-block <div> Contenedor de pre/code Con data-lang, data-title
highlight-box <div> Caja destacada (naranja) Para "Pro Tips"
warning <div> Caja de aviso (amarillo) Para advertencias
notas-css <div> Caja de información (verde) Para notas técnicas
grid-3col <div> Grid de 3 columnas responsive Para matrices de decisión
grid-2col <div> Grid de 2 columnas Para comparativas lado a lado
bullet-list <ul> Lista desordenada estilizada Heredado de styles.css
step-list <ol> Lista ordenada para pasos Heredado de styles.css

10. Atributos data-* Importantes

Atributo Valores Ubicación Propósito
data-section nivel-X-modulo-Y (ej: "nivel-5-troubleshooting") <section> ID único, enlazado con nav data-section
data-mode "technical" | "accessible" | "both" <section> Filtra visibilidad por modo (toggle en topbar)
data-lang bash, python, javascript, json, text, sql <div class="code-block"> Lenguaje para syntax highlighting
data-title Terminal, Código, Salida, etc. <div class="code-block"> Etiqueta visible en esquina superior
data-note Cualquier string <div class="code-block"> Nota adicional (ej: "typescript")

11. Ejemplo Concreto 1: Sección Troubleshooting (Parcial)

HTML Generado (de nivel5-troubleshooting.md):

<!-- ====== SECCIÓN: NIVEL 5 — TROUBLESHOOTING ====== -->
<section class="content-section" data-section="nivel-5-troubleshooting" data-mode="technical">

    <div class="section-header">
        <span class="breadcrumb">Nivel 5 / Troubleshooting</span>
        <h2>🔧 Troubleshooting Avanzado</h2>
        <p class="section-lead">
            Herramientas sistemáticas y flujos de diagnóstico para resolver
            problemas complejos en Claude Code. Desde agotamiento de tokens
            hasta errores de integración con MCP.
        </p>
    </div>

    <!-- BLOQUE 1: Introducción -->
    <h3 class="block-title">🎯 Metodología de Diagnóstico</h3>
    <p>
        Todo problema tiene un patrón. La mayoría de errores en Claude Code
        caen en 5 categorías: Token budget, MCP connectivity, Memory issues,
        Permission errors, y Performance degradation.
    </p>
    <ul class="bullet-list">
        <li><strong>Recopilar evidencia:</strong> Logs, stack traces, contexto</li>
        <li><strong>Aislar variable:</strong> Reduce el input hasta encontrar la causa</li>
        <li><strong>Validar hipótesis:</strong> Verifica tu solución antes de escalar</li>
    </ul>

    <!-- BLOQUE 2: Comando clave -->
    <h3 class="block-title">⚡ Comando Esencial: /context</h3>
    <div class="code-block" data-lang="bash" data-title="Terminal">
        <pre><code>$ claude /context
┌─────────────────────────────────────┐
│ Context Usage (Sesión Actual)       │
├─────────────────────────────────────┤
│ Tokens Usados:    124,850 / 200,000 │
│ % Utilización:    62.4%             │
│ Sistema Prompt:   800 tokens        │
│ Conversación:     124,050 tokens    │
│ Ventana Activa:   ~40K              │
└─────────────────────────────────────┘</code></pre>
    </div>

    <!-- BLOQUE 3: Matriz de Decisión -->
    <h3 class="block-title">📊 Matriz: 5 Problemas Principales</h3>
    <div class="grid-3col">
        <div class="decision-card">
            <h4>📦 Token Budget Agotado</h4>
            <p><strong>Síntoma:</strong> "Context limit exceeded"</p>
            <p><strong>Verificar:</strong></p>
            <ol>
                <li>Ejecutar: <code>/context</code></li>
                <li>Si >85%: Usar <code>/compact</code></li>
            </ol>
        </div>

        <div class="decision-card">
            <h4>🔗 Conexión MCP Rechazada</h4>
            <p><strong>Síntoma:</strong> "Connection refused"</p>
            <p><strong>Verificar:</strong></p>
            <ol>
                <li>Puerto activo: <code>lsof -i :5000</code></li>
                <li>Restart: <code>/mcp restart</code></li>
            </ol>
        </div>

        <div class="decision-card">
            <h4>🚨 Error de Permisos</h4>
            <p><strong>Síntoma:</strong> "Permission denied"</p>
            <p><strong>Verificar:</strong></p>

                <li>Conceder: <code>chmod +r archivo</code></li>
            </ol>
        </div>
    </div>

    <!-- BLOQUE 4: Warning -->
    <div class="warning">
        <strong>⚠️ Cuidado:</strong> No comprimas contexto si hay tokens
        sin procesar. Puede causar pérdida de datos críticos.
    </div>

</section>

13. Checklist de Integración

Antes de integrar sección .md a HTML:

  1. Estructura: Verificar que data-section coincida con nav sidebar
  2. Encabezado: section-header con breadcrumb, h2, section-lead
  3. Bloques h3: Usar class="block-title" para h3 principales
  4. Código: Envolver pre/code en div.code-block con data-lang y data-title
  5. Tablas: Usar <table> con <thead> / <tbody>
  6. Cajas: Usar .highlight-box, .warning, o .notas-css según tipo
  7. Matrices: Usar div.grid-3col o grid-2col para decisión
  8. Listas: Usar class="bullet-list" (ul) o class="step-list" (ol)
  9. Validar: Abrir index.html en navegador, verificar que nav funciona
  10. Modo: Verificar data-mode ("technical", "accessible", "both")
