🔧 MCP Setup: Connecting External Tools & Integrations

Complete guide to installing, configuring, and orchestrating MCPs (Model Context Protocol servers) to extend Claude Code with external APIs, databases, and services. Real configurations, security best practices, and production workflows.

📚 MCP Overview & Architecture

What is the Model Context Protocol?

MCP (Model Context Protocol) is a standardized interface that allows Claude Code to connect to external systems—databases, APIs, file systems, and services—without losing context or breaking your development workflow.

Without MCP
Claude: "Check the database"
You: Copy SQL, paste in terminal
Terminal: Run query, copy results
You: Paste results back to Claude
Claude: Process results, repeat

❌ Manual, slow, context loss

With MCP
Claude: "Query the users table"
MCP (PostgreSQL): Auto-execute
Claude: Receives results instantly
Claude: Analyzes + acts on results
✅ Seamless, fast, full context

✅ Automatic, instant, preserved

How MCPs Extend Claude Code Capabilities

  • Direct Tool Access: Query databases, call APIs, read/write files without manual copy-paste
  • Context Preservation: Entire interaction history stays accessible—Claude remembers what data came from which API
  • Multi-Step Workflows: Chain MCPs: GitHub → Process → Slack → Log. Each step feeds into the next automatically
  • Real-Time Data: Always working with live data, not stale snapshots. Perfect for CI/CD, monitoring, and dynamic systems
  • Secure Credential Handling: API keys, database passwords stored locally, never sent to Claude API

When to Use MCPs vs Built-In Tools

Use MCPs When Use Built-In Tools When
Querying databases repeatedly One-off Bash commands
Integrating with SaaS (Slack, Stripe) File operations on your machine
Long-running workflows (monitoring) Local development tools (npm, git)
Handling sensitive credentials Quick previewing or debugging
Multi-MCP orchestration Things already in your shell environment

The MCP Registry

Public Registry: https://github.com/modelcontextprotocol/servers contains ~50+ official MCPs maintained by Anthropic and the community (PostgreSQL, MySQL, Redis, GitHub, Slack, Google Drive, etc.)

Private MCPs: Build your own to wrap internal APIs, legacy systems, or proprietary tools. Stored in .mcp.local.json for security.

⚙️ Installation & Configuration

Step 1: Install MCP CLI

The MCP CLI is a Node.js package that manages MCP servers for Claude Code.

Bash

npm install -g @anthropic-ai/mcp
mcp --version
# Output: @anthropic-ai/mcp 1.0.0

Alternative (Homebrew on macOS):
brew install @anthropic-ai/mcp

Step 2: Create MCP Configuration Files

MCP uses two configuration files: global config and local secrets.

File: ~/.mcp/config.json (Global)

Stores all installed MCPs and their public settings. Versionable in git.

{
  "version": "1.0",
  "mcps": [
    {
      "name": "github",
      "type": "stdio",
      "command": "node",
      "args": [
        "~/.mcp/servers/github/index.js"
      ],
      "env": {
        "MCP_GITHUB_OWNER": "your-org",
        "MCP_GITHUB_REPO": "your-repo"
      },
      "scope": "project"
    },
    {
      "name": "postgresql",
      "type": "stdio",
      "command": "node",
      "args": [
        "~/.mcp/servers/postgres/index.js"
      ],
      "scope": "global"
    }
  ]
}
File: ~/.mcp/.env.local (Secrets)

API keys, database passwords, tokens. Never commit to git. Added to .gitignore.

# GitHub API
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
GITHUB_API_URL=https://api.github.com

# PostgreSQL
PG_HOST=localhost
PG_PORT=5432
PG_USER=admin
PG_PASSWORD=your_secure_password
PG_DATABASE=production

# Slack
SLACK_BOT_TOKEN=xoxb-xxxxxxxxxxxxxxxxxxxxxxxxxxxx
SLACK_SIGNING_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxx

# Stripe
STRIPE_API_KEY=sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
STRIPE_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxxxxxxxxxx

⚠️ Security: Never commit .env.local. Add to .gitignore immediately.

Step 3: Verify Your Setup

# List all installed MCPs
mcp list

# Test a specific MCP
mcp test github

# Show config status
mcp config --validate

# Check logs
mcp logs --tail 50

Expected output: All MCPs should show ✓ healthy

🎯 Configuration Deep Dive

Global vs Project Scope

Global Scope Project Scope
Stored in: ~/.mcp/config.json Stored in: .mcp.json (project root)
Shared across all projects Specific to one project
Example: PostgreSQL, Redis (dev) Example: GitHub (this repo), Custom APIs
Not in git (personal machine) Can be in git (team shared)

Environment Variables & Credential Management

MCPs support secure credential injection via environment variables. Use ${VAR_NAME} syntax in config files.

Recommended Pattern:
# 1. Store secrets in ~/.mcp/.env.local
cat >> ~/.mcp/.env.local << 'EOF'
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
DATABASE_URL=postgresql://user:pass@localhost/db
EOF

# 2. Source in your shell or Claude session
export $(cat ~/.mcp/.env.local | xargs)

# 3. Reference in config files
{
  "env": {
    "GITHUB_TOKEN": "${GITHUB_TOKEN}",
    "DATABASE_URL": "${DATABASE_URL}"
  }
}

⚠️ NEVER: Commit API keys, passwords, or tokens to git. Use .mcp.local.json for secrets, add to .gitignore.

Multiple MCPs Coordination

When using 3+ MCPs together, coordination matters. Define clear dependencies and order of execution.

Example: GitHub + Slack + Stripe (Auto-notify customers on deploy)
{
  "version": "1.0",
  "mcps": [
    {
      "name": "github",
      "command": "node",
      "args": ["~/.mcp/servers/github/index.js"],
      "order": 1,
      "dependencies": []
    },
    {
      "name": "stripe",
      "command": "node",
      "args": ["~/.mcp/servers/stripe/index.js"],
      "order": 2,
      "dependencies": ["github"]
    },
    {
      "name": "slack",
      "command": "node",
      "args": ["~/.mcp/servers/slack/index.js"],
      "order": 3,
      "dependencies": ["github", "stripe"]
    }
  ]
}

Workflow: GitHub detects deploy → Stripe queries affected customers → Slack notifies each customer in DM → All coordinated in one context.

Version Pinning & Updates

Keep MCPs stable by pinning versions. Auto-updates can break workflows.

{
  "mcps": [
    {
      "name": "postgresql",
      "version": "1.2.3",
      "checkForUpdates": true,
      "updateChannel": "stable",
      "rollbackOnFailure": true
    }
  ]
}

Check for updates:

mcp update --check
mcp update postgresql@1.3.0 # Pin specific version

🚀 Real-World Integration Examples

Example 1: GitHub + Slack — Auto-Review PRs & Notify Team

Scenario: Whenever a PR arrives, Claude reviews it and posts results to Slack.

Step 1: Configure MCPs
{
  "version": "1.0",
  "mcps": [
    {
      "name": "github",
      "command": "node",
      "args": ["~/.mcp/servers/github/index.js"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}",
        "GITHUB_OWNER": "my-org",
        "GITHUB_REPO": "backend"
      }
    },
    {
      "name": "slack",
      "command": "node",
      "args": ["~/.mcp/servers/slack/index.js"],
      "env": {
        "SLACK_BOT_TOKEN": "${SLACK_BOT_TOKEN}",
        "SLACK_CHANNEL": "#code-reviews"
      }
    }
  ]
}
Step 2: Create GitHub Action Trigger
# .github/workflows/pr-review.yml
name: Auto-Review PR

on: [pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Review PR with Claude
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          SLACK_BOT_TOKEN: ${{ secrets.SLACK_BOT_TOKEN }}
        run: |
          mcp run github --action "review-pr" --pr ${{ github.event.pull_request.number }}
          mcp run slack --action "post-review"
Expected Output

Slack message to #code-reviews:

✅ PR #42: Add user authentication
Changes: 350 lines | Security: Looks good | Tests: ✅ Pass
Comment added to PR with detailed suggestions

Example 3: Multi-MCP Orchestration — Deploy Workflow

Scenario: Full deployment pipeline: GitHub PR → Merge → DB Migration → Slack Notification → Health Check

Orchestration Config

          "action": "check-endpoint",
          "url": "https://api.example.com/health",
          "expectedStatus": 200,
          "onFailure": "rollback"
        }
      ]
    }
  ]
}

🐛 Troubleshooting Guide

❌ MCP not found error

Error: Error: MCP 'postgresql' not found

Solutions:

  1. Verify MCP is installed: mcp list
  2. Check config file path: mcp config --validate
  3. Reinstall: mcp add postgresql --scope global
  4. Check project scope: Ensure .mcp.json exists in project root

❌ Permission denied errors

Error: permission denied: ~/.mcp/servers/github/index.js

Fix:

chmod +x ~/.mcp/servers/*/index.js
chmod +x ~/.mcp/servers/*/bin/*

❌ Credential/Auth Issues

Error: 401 Unauthorized: Invalid GitHub token

Solutions:

  1. Verify token in environment: echo $GITHUB_TOKEN
  2. Check token expiration: GitHub Settings → Developer Settings → Personal Access Tokens
  3. Verify scopes: Token should have repo, read:org scopes
  4. Regenerate token: mcp auth github --refresh

❌ Slow or Timing Out MCPs

Error: MCP timeout after 30s

Fixes:

{
  "mcp": "postgresql",
  "timeout": 60000,  # Increase to 60 seconds
  "retries": 3,      # Retry failed queries
  "pool": {
    "max": 5,        # Max concurrent queries
    "idleTimeoutMillis": 30000
  }
}

Or optimize queries:

  1. Add indexes: CREATE INDEX idx_users_email ON users(email)
  2. Use LIMIT: Avoid querying millions of rows at once
  3. Cache results: Store in Redis for repeat queries

✅ Testing MCPs Before Deployment

Always validate MCPs before using in production workflows.

# Test individual MCP
mcp test postgresql

# Test with sample query
mcp test postgresql --query "SELECT 1"

# Test all MCPs
mcp test --all

# Show detailed logs
mcp test postgresql --verbose

✦ Best Practices & Security

1. Test MCPs in Isolation

Never deploy an untested MCP to production. Always validate in a dev environment first.

# Create dev MCP config
cp ~/.mcp/config.json ~/.mcp/config.dev.json

# Point to dev database
mcp test postgresql --config ~/.mcp/config.dev.json

# Run integration tests
npm run test:mcp

2. Limit MCP Output Tokens

Large query results can bloat token usage. Always LIMIT results and paginate if needed.

-- ❌ BAD: Query millions of rows
SELECT * FROM events

-- ✅ GOOD: Explicit LIMIT
SELECT * FROM events WHERE created_at > NOW() - INTERVAL '1 day' LIMIT 100

-- ✅ GOOD: Pagination
SELECT * FROM users OFFSET 0 LIMIT 50 # Page 1
SELECT * FROM users OFFSET 50 LIMIT 50 # Page 2

3. Handle MCP Failures Gracefully

When MCPs fail, always have fallback logic.

try {
  const result = await mcp.postgresql.query("SELECT ...");
} catch (error) {
  if (error.code === 'TIMEOUT') {
    console.log('Query timeout, using cached result');
    return cachedData;
  } else if (error.code === 'UNAVAILABLE') {
    console.log('Database down, alerting ops');
    await mcp.slack.send('DB unavailable!');
  }
}

4. Monitor MCP Usage & Costs

Track API calls and token usage to avoid surprise bills.

# Enable MCP logging
mcp config set log-level=debug

# View usage stats
mcp stats

# Set usage alerts
mcp config set cost-alert=100 # Alert at $100 spend

5. Security Best Practices

  • Never log credentials: Disable logging for sensitive MCPs in production
  • Rotate tokens regularly: Set 90-day rotation for API keys, database passwords
  • Use read-only credentials when possible: GitHub: use read:repository scopes
  • Audit MCP access: Log all queries, API calls. Use database audit logs.
  • Isolate sensitive MCPs: Keep Stripe, payment MCPs in separate config with restricted access
  • VPN for production: Connect to production databases only through VPN or bastion hosts
  • Encrypt MCP configs: Use gpg or sops to encrypt sensitive configs
